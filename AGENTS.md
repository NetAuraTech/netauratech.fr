This is `netauratech.fr` — the NetAuraTech site: a content-driven public front (portfolio, services, contact) and an authenticated admin back-office, built on the Foundry 2.0 baseline (the `inertia` flavor of `adonisjs-foundry` v2.0.0: AdonisJS v7 + Inertia/React), on a domain-driven architecture (controllers → services/repositories → models).

<critical>
- Prefer `npm` for dependency management and scripts.
- Never manually modify files in `apps/web/.adonisjs/`; they are generated by AdonisJS and updated by the framework.
- Node >= 24 (enforced by `engines` in both workspaces).
</critical>

## Repository layout

Two-workspace npm monorepo, single lockfile at the root:

- `apps/web/` (`@foundry/web`) — the complete AdonisJS application: the transport layer (`app/`), the business layer (`src/`), the Inertia frontend (`inertia/`), the site content sources (`content/`), config, database, providers, ace commands, and the Japa/Vitest suites.
- `packages/design-system/` (`@foundry/design-system`) — the source-only React design-system package (tokens + atoms/molecules/organisms), consumed by the app as a workspace dependency.

The repo root holds the workspaces manifest, the lockfile, the oxlint/oxfmt configs, CI, Docker and docs.

## Conventions

- `node ace` commands run from `apps/web/`; the npm scripts (`dev`, `build`, `test`, `test:front`, `lint`, `format`, `typecheck`) run from the repo root (they proxy to the workspace). All code paths in `docs/agents/` are relative to `apps/web/` unless stated otherwise.
- **Per-domain BFF layout.** Business code lives in `src/{domain}/` (actions, services, repositories, queries, models, exceptions) and is imported through the per-domain alias (`#file/...`, `#core/...`, …). Transport code lives in `app/{domain}/` (controllers, routes, validators, transformers) and is imported through the single `#transport/*` alias. The domains are `account`, `auth`, `backup`, `core`, `file`, `identity`, `log` and `shared`.
- **`core.*.render` route naming.** Public GET routes are named `core.{page}.render` (`core.home.render`, `core.projects.render`, `core.projects.show.render`, `core.services.render`); every parameter-free one is collected into `sitemap.xml` automatically.
- **Design system.** Shared presentation lives in `@foundry/design-system` (source-only; the `exports` map is the public API). The app keeps only the workflow- or app-coupled components. See `docs/agents/design-system.md`.

## The NetAuraTech site

The public front is content-driven: no CMS, no page persistence.

- **Public pages** — `/` (home), `/projets` (portfolio), `/projets/:slug` (one shared project controller) and `/services`. Each is a thin controller in `app/core/controllers/front/` rendering a hand-written Inertia page (`inertia/pages/core/front/`); the shared header/footer nav lives in `inertia/layouts/default.tsx`.
- **Content sources** — committed markdown in `content/projects/{slug}.md` and `content/services/{slug}.md`: frontmatter (`order`, `cover` (a backend file id), `rubrique`, `title`, `note`) and a structured body — `:::` fenced blocks (`lede`, `features`, `quote`, `gallery`, `metrics`) plus `##` chapters — parsed by `src/core/services/project_blocks.ts` and orchestrated by `src/core/services/site_content_service.ts`.
- **Adding a project** — drop `content/projects/{slug}.md`. The route, the page and the sitemap pick it up with no code change.
- **Sitemap** — `start/sitemap.ts` registers two collectors (the route collector and the projects collector, `src/core/services/`) into a shared registry; `SitemapService` aggregates them plus the `SITEMAP_ADDITIONS` / `SITEMAP_EXCLUSIONS` env values.
- **Contact** — the `contact_form` organism is a client-side `mailto:` form (recipient from `MAIL_FROM_ADDRESS`); nothing is written to the database.
- **Project visuals** — `cover` and gallery `id:N` references resolve through the `file` domain (`FindFileAction` → server-resolved URLs and responsive WebP variants); images are never committed to the repo.

## Repository Expectations

- Run `npm run lint`, `npm run format`, `npm run typecheck`, and `npm run test:front` before committing code.
- Use Conventional Commits, with the description in the commit body rather than the title:
  type(scope)
  short description
  Optional body listing what was added, changed, or removed.

Types: `feat`, `fix`, `refactor`, `docs`, `chore`, `test`, `perf`. Prefer scopes that match the touched feature, e.g. `feat(front)`, `fix(file)`, `refactor(backup)`.
